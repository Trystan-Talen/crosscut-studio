# 阶段3独立审查：功能规格与架构

日期：2026-10-13（用户时区）；审查角色：工具调查代理独立复评。

审查对象：`docs/03-functional-spec.md`、`docs/adr/001-architecture.md`。
对照证据：`OBS-tools.md`、`OBS-tools-supplement.md`、`OBS-creative.md`。本轮仅修改上述两份合同文档及本审查记录，无业务代码或远程账号变更。

## 结论

**通过，允许进入实现阶段。** 这里的通过指合同具备实施与验收条件，不代表功能已实现，不代表外部AI真实推理已验证。第三方能力缺配置/缺直接适配的交付缺口必须持续明示。

## 已发现并直接修复的问题

1. **P1：本地应用与数据不上传表述易形成错误承诺。** 原文“SQLite与媒体文件本地保存”未明确AI调用会向配置的服务商发送必要输入。现已明确本地默认存储与外部推理边界、提交前可见服务商及输入类型。
2. **P1：泛称provider不足以形成可执行实现合同。** 数字人、商品交互、无痕修复和口型能力不能由普通文本端点完成。补充能力注册、协议、真实模型ID、验证等级、异步schema和兼容网关边界；禁止仅有URL和密钥就声称全部工具可用。
3. **P1：跨语言字幕与混剪语言选择存在隐式伪实现风险。** 原语ASR、翻译、烧录分离；本地混剪只使用已明确提供的目标语言文字，缺翻译能力不假称自动翻译。
4. **P1：外部提交结果不明时的重试可能重复收费。** 补充待核对状态与幂等/已受理查询；无法确认未受理时禁止自动重提交。
5. **P1：批量与取消合同缺父子状态规则。** 增加父批次、子任务、部分成功、独立重试与保留已成功产物，新增对应可执行验收。
6. **P1：SQLite备份与主密钥恢复边界不完整。** 补充一致性备份、WAL注意、独立密钥导出、失钥后重新配置provider及隔离恢复测试。
7. **P2：表单契约遗漏模型文件差异、商品数字人比例、混剪推荐时长、字幕真实样式等。** 已与原站观察对齐；新增项或未观察规则明确标为DEC。未把原站不可用工作流、收费矛盾或未验证参数当可靠保证。
8. **P2：17工具验收过于笼统，未覆盖Agent、工作流、角色库、字幕与外部异常。** 新增A13–A18及每项证据格式；不把fixture成功当真实推理成功。
9. **P2：媒体worker资源和命令安全缺少明确约束。** 补充参数数组、隔离临时目录、路径/符号链接、输入下载、任务限额、子进程组取消，以及FFmpeg中文字体/滤镜诊断。
10. **P1：本地终态取消不能套用于远程running。** 对照provider契约研究，将本地已终止、远程accepted与远程确认cancelled分开。不能为取消误用具有删除记录语义的DELETE，远程不支持时继续查询真实状态。

## 实施时必须保留的交付边界

- 原站效果等同、专有素材库、隐藏算法和真实付费生成结果仍未验证；最终不能宣称无条件全功能对等。
- 数字人素材/音色需用户自有或供应商授权目录；不能复制原站库作为本项目资产。
- 模型适配必须依据真实官方协议。通用网关需要用户提供兼容网关，不能当作已经连接原厂服务。
- 本地FFmpeg混剪、转码、裁切、字幕烧录要生成真实可解码媒体，不能以随机延时与样片冒充结果。
- 此阶段新增的安全上限和混剪推荐时长是独立产品决策，实施时须在UI显示；不能冒充参考平台隐藏规则。
