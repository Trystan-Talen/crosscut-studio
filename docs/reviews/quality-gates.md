# 阶段质量门槛

每个阶段应由主实现者自评，再接受独立审阅。发现的问题必须记录修正与复验结果。

| 阶段 | 通过条件 |
| --- | --- |
| 范围 | 所有可访问导航入口编号；角色、任务、受限入口和未知能力有记录；全部功能有可清点基数。 |
| 调查 | 模块正常流程、空状态、校验/失败及持久化行为有观察记录；事实/推断/未验证明确区分。 |
| 规格 | 每项输入、规则、输出、数据、权限、状态与验收用例可追踪；外部服务配置条件明确。 |
| 设计 | 核心流程无断点；窄屏、加载、错误、空状态、危险操作和键盘焦点有统一处理。 |
| 开发 | 真实端到端链路、迁移、事务、数据隔离、重启恢复通过；类型检查、构建与必要测试通过。 |
| 验收 | 功能逐项关联实现与测试；关键流程真实存储；P0/P1 缺陷清零；未配置服务单独列出。 |

## 审查记录格式
发现 → 严重度 → 修正 → 复验 → 是否通过。

主观满意不能代替实际证据；外部能力未实测不能标记为完成。

### 外部能力的独立门槛

- 配置保存、代码存在、协议fixture通过、真实模型调用成功是不同证据。未提供真实凭据时，AI只能标“适配器已实现/契约已验证/待真实联调”。
- 官方OpenAI兼容、Ark、ElevenLabs、HeyGen适配器的fixture可证明请求、状态/恢复、媒体传输及本地校验；不能证明账户资格、额度、语义准确性、人物/声音/视频生成质量。
- 自定义`workflow-http-v1`只有外接协议实现。手持商品、爆款复刻、链接成片和智能字幕修复需真正的兼容服务；通用fixture返回视频不能满足业务模型门槛。
- 本地确定性后期、原创字幕静态预设、技术镜头检测按实际产物验收。遮挡/裁切不记无痕修复，技术分镜不记语义分析，多语言选择不记自动翻译。
- Mac启动/备份已有专项记录，见[scripts/VERIFICATION.md](../../scripts/VERIFICATION.md)；命令行等价调用不自动代替未记录的Finder人工操作。

发现的问题须在最终统一版本复验；最终检查已完成，不以其通过率、工具入口数量或主观满意代替真实AI与完整业务验收签署。
