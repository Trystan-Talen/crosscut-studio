调查日期：2026-10-13（用户时区 America/Los_Angeles）。来源：已授权登录的 Tec-Creative 浏览器页面，独立调查标签页；仅通过界面、可访问性树、DOM 中表单属性读取。账号积分显示 0/0。未上传任何用户文件、未提交生成、未购买、未删除或修改历史内容。

标记：**OBS** 为实际观察；**INF** 为实现建议或推断；**BLOCK** 为尚未验证。下文显示的积分只是空表单按钮上的值，不代表已验证的实际计费规则。

## 规格与架构建议（INF，不是原平台后台事实）

1. 工具定义应数据驱动：工具目录、输入 schema、模型能力、字段依赖、上传限制、预估成本、输出类型分离。不能让所有工具复用同一段假生成逻辑。
2. 统一持久化任务状态：草稿、等待依赖、排队、执行、成功、部分成功、失败、取消；关联输入快照、素材、模型、供应商任务 ID、真实错误与产物。
3. SQLite 保存业务元数据和任务事件；媒体存本地受控目录，数据库仅存路径、哈希、MIME、字节数、时长、尺寸、授权来源。
4. 图像/视频生成、数字人、克隆、ASR、TTS、翻译应通过有类型的供应商适配器实现。无密钥时明确显示“未配置”，不得输出假视频或把样例当本次生成结果。
5. 可本地完成的混剪、转码、字幕烧录、音量/时长裁切用真实媒体处理流水线，保留执行日志和可下载文件。语义脚本选择或识别属于独立模型能力，不能用拼接冒充。
6. 数字人库和音色库需要带授权元数据的自有/供应商目录。参考平台素材不应批量复制到交付项目。
7. 新 UI 以创作任务为核心：步骤式素材→脚本→人声/角色→成片；上下文保留和结果可再编辑，复杂可选参数收纳为高级设置。
8. 文件限制应在客户端与服务器都验证，包括 MIME/内容校验、数量、尺寸、时长；文件名安全、路径隔离和超额拒绝要有明确错误。
